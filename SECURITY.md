# Security Policy — cirnet-hardware

Follow the [CIRNETLAB security policy](https://github.com/cirnetlab/.github/blob/main/SECURITY.md). Report vulnerabilities privately through Security → Advisories → Report a vulnerability when available. Otherwise request a private contact in a public issue without disclosing sensitive details. Identify affected revision, impact and safe reproduction. Never post secrets or personal data.

Maintained revisions are eligible for reports; no guaranteed support period or response SLA. Use authorized, isolated tests only. For physical hardware, fail closed, do not energize unknown circuits and require verified shutdown; software correctness does not establish electrical safety.

Review RPC authentication/authorization, worker identity, timeouts, cancellation, station isolation and electrical safety before release. Review dependency advisories, workflow permissions and access controls. This policy is not a completed vulnerability audit.
